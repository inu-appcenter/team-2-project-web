# 커밋 컨벤션

## 1. 목적

커밋 메시지만으로 변경 목적을 빠르게 파악할 수 있도록 일관된 형식을 사용한다.
하나의 커밋에는 하나의 논리적인 변경만 포함한다.

## 2. 기본 형식

```text
<emoji> <commit type> : <description>
```

예시:

```text
✨ feat : 연구실 목록 조회 기능 추가
🐛 fix : 모집 상태 필터가 초기화되는 오류 수정
📝 docs : 개발 컨벤션 문서 추가
```

### 작성 규칙

- 커밋 타입은 영문 소문자로 작성한다.
- 타입 앞에는 해당 타입의 이모지를 붙인다.
- 타입과 콜론(`:`) 사이에는 공백을 한 칸 둔다.
- 설명은 한글로 간결하게 작성하고, 문장 끝에 마침표를 붙이지 않는다.
- 설명은 무엇을 변경했는지가 드러나도록 작성한다.
- 여러 목적의 변경은 가능한 한 별도 커밋으로 분리한다.

## 3. 커밋 타입

| 이모지 | 타입 | 사용 기준 | 예시 |
| --- | --- | --- | --- |
| ✨ | `feat` | 새로운 기능 추가 | `✨ feat : 연구실 검색 기능 추가` |
| 🐛 | `fix` | 버그 수정 | `🐛 fix : 로그인 후 경로가 유지되지 않는 오류 수정` |
| 📝 | `docs` | 문서 추가 및 변경 | `📝 docs : API 연동 가이드 작성` |
| 💄 | `style` | 동작에 영향을 주지 않는 코드 스타일 변경 | `💄 style : ESLint 규칙에 맞게 코드 정리` |
| ♻️ | `refactor` | 기능 변경 없는 코드 구조 개선 | `♻️ refactor : 연구실 필터 로직 분리` |
| ⚡ | `perf` | 성능 개선 | `⚡ perf : 연구실 이미지 로딩 최적화` |
| ✅ | `test` | 테스트 추가 및 수정 | `✅ test : 연구실 카드 컴포넌트 테스트 추가` |
| 🔧 | `chore` | 빌드, 설정, 의존성 및 기타 작업 | `🔧 chore : Storybook 설정 추가` |
| 🎨 | `design` | 사용자에게 보이는 UI/UX 변경 | `🎨 design : 연구실 상세 페이지 레이아웃 개선` |
| 🔒 | `security` | 보안 관련 변경 | `🔒 security : 사용자 입력값 검증 강화` |
| 🚀 | `deploy` | 배포 및 배포 환경 변경 | `🚀 deploy : 프로덕션 배포 워크플로 추가` |

## 4. 제목과 본문

간단한 변경은 제목만 작성한다. 변경 이유나 영향 범위에 대한 설명이 필요하면 제목 아래에 본문을 추가한다.

```text
✨ feat : 연구실 모집 상태 필터 추가

- 상시 모집, 모집 중, 모집 마감 상태를 선택할 수 있도록 구현
- 선택한 필터를 URL 쿼리 파라미터와 동기화
```

관련 이슈가 있다면 본문 마지막에 이슈 번호를 작성한다.

```text
Related to: #12
Closes: #12
```

- `Related to`: 해당 이슈와 관련은 있지만 커밋만으로 이슈를 종료하지 않을 때 사용한다.
- `Closes`: 변경이 병합되면 이슈를 종료해도 될 때 사용한다.

## 5. 피해야 할 메시지

변경 내용을 파악하기 어려운 표현은 사용하지 않는다.

```text
수정
버그 해결
작업 중
코드 변경
✨ feat : 기능 추가
```

무엇을 변경했는지 구체적으로 작성한다.

```text
🐛 fix : 연구실 상세 페이지의 빈 후기 처리 오류 수정
```
